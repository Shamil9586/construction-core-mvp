# Construction Core — Parallel Design Work Context

## Purpose

Этот документ передается в параллельную Design/UX сессию, чтобы она понимала текущий статус Construction Core и не затронула параллельную backend-работу.

Design-сессия работает отдельно от:

- ROLE-CLEANUP;
- backend;
- auth;
- permissions;
- database migrations.

## Запрещенный для Design scope

Не менять:

- роли;
- права доступа;
- backend domain;
- PostgreSQL schema;
- migrations;
- seed;
- authentication;
- Render;
- canonical branches.

Любое предложение, требующее изменения этих областей, оформлять только как:

"Design proposal requiring architecture review".

## Текущая архитектура продукта

Construction Core:

- Bitrix24 используется для идентификации, пользователей, оргструктуры и интеграций.
- Core имеет собственный Frontend, Backend и PostgreSQL.
- Не строится как CRM на Bitrix сущностях.

## Текущая управленческая модель

Единая управленческая роль: `DEPUTY_DIRECTOR`

Название в UI: "Заместитель директора".

Старые роли выводятся из модели:

- TECHNICAL_DIRECTOR;
- DEPARTMENT_HEAD;
- отдельный Директор по строительству.

Это отдельный backend ROLE-CLEANUP процесс.

Design не должен возвращать эти роли в UI.

## Главные UX-принципы

### 1. Не смешивать объекты

Главное правило:

Пользователь сначала выбирает объект, затем работает внутри объекта.

Компания: C01 → карточки объектов → выбранный объект.

Не создавать экраны, где одновременно смешивается операционная работа нескольких объектов.

## Основные экраны

### C01 — Company Control Center

Назначение: Управленческий центр компании.

Показывает:

- портфель объектов;
- физическую готовность СМР;
- состояние графика;
- очередь внимания;
- причины отклонений;
- ответственных.

Не смешивать сюда:

- ИД;
- контроль качества;
- финансовое закрытие.

### O01 — Object Overview

Назначение: Быстро понять состояние одного объекта.

Показывает:

- название;
- адрес;
- заказчика;
- ответственных;
- физическую готовность СМР;
- состояние графика.

Правильные формулировки:

- "По графику";
- "Есть отставание".

Причины:

- задержка материалов;
- невыданы решения;
- проблемы мобилизации;
- блокировки производства.

### W01 — Work Card

Центральная производственная сущность.

Работа состоит из:

- вида работ;
- типа отделки;
- пирога этапов;
- условий;
- захватки/зоны;
- исполнителя.

Пример:

Отделочные работы

Тип №1: штукатурка → шпаклевка → покраска

Зона: 1 этаж / 500 м²

Подтверждение объемов

История неизменяемая.

Пример:

- РП факт: 500 м²
- Внутренний СК: 498 м²
- СК заказчика: 496 м²

Нельзя перезаписывать прошлые подтверждения.

## Команды и назначения

Главный принцип: Смена руководителя не уничтожает команду.

Пример: Начальник ПТО увольняется.

Новый начальник ПТО:

- может оставить существующих инженеров;
- может заменить часть команды;
- может принять объект с текущей командой.

То же относится к:

- РП;
- СК;
- СДО.

UI не должен предполагать: "смена руководителя = очистить команду".

## Design-задача

Разрешено:

- улучшать UX;
- создавать прототипы;
- менять визуальную иерархию;
- улучшать адаптив;
- готовить следующие UI этапы.

Основные направления:

1. C01.
2. O01.
3. W01.
4. Object onboarding.
5. Представление команд и назначений.
6. Mobile UX.
7. Единый визуальный язык.

## Результат Design-сессии

Нужно подготовить:

- UX решения;
- прототипы;
- спецификации экранов;
- рекомендации для следующей frontend реализации.

Не менять backend контракт без отдельного архитектурного решения.
