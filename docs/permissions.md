# Доступ

Авторитетная матрица — Permission enum и grants в `packages/domain/index.ts`. Все mutations проверяют backend permission до изменения БД.

| Роль | Возможности |
|---|---|
| ADMIN | Все операции, справочники, пользователи, импорт, настройки |
| GENERAL_DIRECTOR | Просмотр объектов, производства, ИД, СДО, финансов и аудита |
| DEPUTY_DIRECTOR | Канонический текущий управленческий роль (F12.3, «Заместитель директора»): просмотр обоих контуров (строительного и технического), создание/редактирование объектов и работ, переназначение РП, аудит — те же управленческие права, что раньше были у TECHNICAL_DIRECTOR. Не выполняет операционные действия ПТО/СДО/СК (нет DOCUMENTATION_MANAGE, SDO_CASE_MANAGE, INSPECTION_ACCEPT/REJECT) |
| TECHNICAL_DIRECTOR | Просмотр, создание объектов/работ, аудит. Устаревшая роль, сохранена для совместимости с уже назначенными пользователями/историческими данными — новым назначениям использовать DEPUTY_DIRECTOR |
| PROJECT_MANAGER | Собственные объекты, работы, факт, предъявление СК, устранение замечаний |
| CONSTRUCTION_CONTROL | Замечания, фото, проверка устранения, приёмка/отклонение |
| PTO | Материалы, ИД, подготовка и передача комплекта |
| SDO | Ввод расчёта, финансовое закрытие |
| DEPARTMENT_HEAD | Просмотр |
| CONTRACTOR_VIEWER | Связанные объекты и свои работы; без финансов |

Проект не считает email внешним ключом; используется bitrixUserId внутри tenant. Установка создаёт только заранее настроенного ADMIN. Остальных назначает администратор приложения. Автоматического повышения роли из входящего payload нет. Для production понадобятся детальные ограничения руководителей по подразделениям и периодический отзыв доступа у деактивированных сотрудников Bitrix.
