# Бизнес-правила

1. Факт: min(100, actualQuantity / plannedQuantity * 100). ActualQuantity может превышать план. Плановый объём должен быть больше нуля.
2. Плановая готовность линейная; до начала 0, после срока 100. Нулевая длительность: на дату срока — 100. Порог GREEN ≥ −5 п.п.; YELLOW от −15 до −5; RED < −15. Настройки в risk_settings, доступны администратору.
3. delayDays — отставание от эквивалентной даты линейного графика при текущем выполненном объёме, а не CPM-прогноз. Для завершённой работы ноль. Нет свежего факта — GRAY, если нет более сильного риска.
4. Готовность объекта взвешивается ориентировочной стоимостью работ; при нулевой стоимости — среднее. Это управленческая оценка, не доля финансового закрытия.
5. FINISH_TO_START: предыдущая работа завершена, при необходимости принята СК; критические замечания и обязательный неподтверждённый документ блокируют переход. Циклы и зависимости между разными объектами запрещены. Зависимость добавляется только до начала следующей работы.
6. После предъявления СК изменение факта блокируется. Для MVP предъявляется полный объём. Замечание: OPEN → READY_FOR_VERIFICATION (РП) → CLOSED (СК). Приёмка невозможна без фото и пока замечания не закрыты СК.
7. ПТО: пакет включает подтверждённый АОСР, все включённые документы APPROVED, требуемую приёмку СК, материалы с действующими документами партии. Сначала READY, затем TRANSFERRED_TO_SDO. Сгенерированный текст всегда DRAFT; подтверждение требует загруженного файла.
8. СДО получает комплект; стоимость рассчитывает во внешней программе. Одно дело СДО на работу в MVP. Закрытия частями допустимы в пределах acceptedClosingValue. Суммы Decimal, не float. Повтор idempotencyKey не создаёт второе закрытие.
9. Потенциал работы = max(0, стоимость выполненного объёма − закрыто). Разбивка по стадиям непересекающаяся. Выполнение для расчёта ограничено 100%. Потенциал объекта — сумма потенциалов работ. Если исполнительная смета отличается от ориентировочной стоимости, возникает оценочная разница; перерасход по одной работе не взаимозачитывается с другой.
10. Прогноз MVP = закрыто в текущем месяце + рассчитанные ещё не закрытые суммы. Это управленческая оценка доступного закрытия, без прогноза будущей скорости и клиентской оплаты.
11. Денежный эффект attentionRequired повторяется у нескольких проблем одной работы. Строки attentionRequired нельзя суммировать. KPI рассчитывается отдельно.
12. Excel: source + УКО — ключ первоначального импорта. ГПО → ООО СЗ «Гор-Строй». СПО/РКС-НР → организация из СПО. Масштаб денег выбирает оператор. Тип плана хранится единым plannedValue + INTERMEDIATE/FINAL; без явного типа план не импортируется. Цвет сам по себе не признаётся надёжной классификацией. Факт СМР из денежных сумм не восстанавливается. Строки с пустым адресом/УКО/организацией или недопустимой суммой блокируются.
